# Instructions for future coding agents

1. Inspect the tree, Git status, current scenes, resources, and tests before editing. Preserve user changes and working behavior. This directory is the project root; never initialize Git in its parent.
2. Read README.md, docs/technical-design.md, docs/roadmap.md, the latest development-log entry, and design documents relevant to your task.
3. Implement only the requested milestone. Movement, cyberware, saves, dialogue, hazards, and bosses are future work until separately authorized. Avoid empty manager scripts and speculative abstractions.
4. Use snake_case filenames, PascalCase node/class names, snake_case methods/signals, typed GDScript where useful, and res:// resource paths. Keep scenes composable and dependencies explicit.
5. Read semantic InputMap actions. Do not scatter physical-key checks. Keep movement on fixed physics ticks, independent of animation. Both difficulty modes share physics parameters.
6. Prefer scene-local ownership and Godot Resources/signals. Add an autoload only with a documented lifetime requirement; avoid circular dependencies and global event buses without evidence.
7. Run tests appropriate to changes. At minimum run tests/validate_static.ps1, Godot headless import, startup and tests/smoke_test.gd when the engine is available. Visually verify UI changes in Godot. Report exact checks executed and distinguish failures, skipped checks, and unavailable tools.
8. Never claim an implementation or milestone is complete without relevant validation. Static text checks cannot establish engine compatibility, rendering, or gameplay correctness.
9. Document new systems, interfaces, parameter units, and architectural decisions; distinguish approved rules from untested proposals. Update docs/development-log.md after substantial changes and keep the roadmap/status accurate.
10. Keep changes focused and reviewable. Do not rewrite functioning systems gratuitously, discard user files, install software, move the project, or modify OneDrive settings without appropriate authorization.
11. Use original assets or placeholders. Do not download/extract copyrighted sprites, music, fonts, or proprietary game files without permission. Record provenance/license before importing third-party work. Narrative IDs must allow replacing fan-project names.
12. Keep .godot/, export output, credentials, logs and editor state out of Git. Preserve source .uid and .import sidecars. Do not push unless instructed.
13. Engine confirmed at initialization: Godot 4.7.2 stable (`4.7.2.stable.official.ed1daf0bf`). Recheck --version on new machines and record any agreed engine change. Under a restricted agent sandbox isolate editor/user-data and logs in ignored .godot paths as described in README; do not alter production paths to bypass tooling restrictions.
14. Keep files local and accessible under OneDrive. If synchronization/locking errors arise, report them; never silently relocate the project. See README for mitigation.
15. M01 player movement is now implemented and measured. Preserve charge/release, tap minimum, neutral A+D, no default air steering, cancellation on pause/focus/reset, and state/landing behavior unless the current task intentionally changes them. Read docs/physics-spec.md before touching movement or geometry.
16. Physics defaults live in resources/physics/default_player_physics.tres; launch formulas live only in JumpPhysics. PlayerController owns movement; Visual/HUD/camera/recorder must not modify velocity. Do not introduce duplicate physics formulas or change difficulty-specific jump reach.
17. After physics/input/collision/camera changes, run `godot --headless --editor --path . --import`, `godot --headless --path . --script res://tests/smoke_test.gd`, and `godot --headless --fixed-fps 60 --path . --script res://tests/physics_test.gd` with the actual confirmed executable. On Windows use `tests/run_validation.ps1 -GodotExe <path>` for isolated AppData/logs. Also run `powershell -NoProfile -ExecutionPolicy Bypass -File tests/validate_static.ps1`.
18. Inspect measured charge envelopes and the twelve-platform route after tuning. Update physics-spec/level-design/development-log with changed values and rationale. Never loosen collision/reachability tests to hide an impossible route or claim automated success proves subjective feel. Reset tests must reacquire solver floor contact after teleport.
19. The user explicitly authorized controller refinement in M02B, superseding the 02A controller freeze. The controller's old hash guard was intentionally replaced by behavioral surface/trajectory regressions; JumpPhysics, default launch Resource, collider scene and LabCamera still retain their original hash checks. Preserve the measured normal envelope unless a future task intentionally authorizes retuning. Never change guards simply to hide regressions.
20. Read docs/visual-style-guide.md and docs/asset-manifest.md before art changes. Edit tools/generate_art.gd as the pixel-art source, regenerate PNG/FNT assets, import, then run all suites including `godot --headless --fixed-fps 60 --path . --script res://tests/visual_prototype_test.gd`. Preserve lossless/no-mipmap/nearest imports and 1:1 pixel density.
21. Reuse IndustrialPlatform, IndustrialFixture and IndustrialArt for established visuals. Decorative artwork must not gain invisible collision/hazards. M02B adds mechanics fixtures only; preserve existing chamber/art and do not begin future production/narrative work without its own prompt.
22. Capture actual engine views with tools/capture_visual_review.gd, inspect native and integer-scaled images, and document visual refinements. Review captures stage the player for composition; do not claim manual traversal or artistic approval from them. Keep docs/visual-review/.gdignore so screenshot assets are not imported as game textures.
23. Read current physics-spec.md before editing contacts. Baseline launch tuning, SurfacePhysicsProfile, CollisionResponseProfile and live player state are separate. Untagged bodies are normal; metadata selects a Resource, never branch on a node's display name. Do not feed solver contact pressure or stale platform carry into runtime momentum.
24. Keep PhysicsSurface polygons aligned with their drawn boundaries, preserve normal-slope rest, bounded gravity ramps, explicit charge eligibility and no implicit departure boost. Profile seams change coefficients next tick; landings apply explicit retention. No automatic ledge assist or midair steering should be added incidentally.
25. Run the full validation runner after movement/surface changes: it includes existing regressions, `tests/surface_physics_test.gd` at 60Hz and `tests/frame_rate_probe.gd` at 30/60/120 render cadences. Inspect .godot/surface_measurements.json and jump measurements, rerun both actual routes, and report real results. All Lab 2.0 sections must remain directly selectable with supported spawns and correct F6/paused/reset behavior.
